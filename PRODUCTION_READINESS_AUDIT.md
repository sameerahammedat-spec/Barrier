**Audit date:** 2026-11-20

## Executive status

**Not production-ready.** Account, backup, and multiple protection controls are either demo implementations, disabled, or disconnected from their enforcement paths. Release also needs an explicit database upgrade strategy, capability status, device testing, policy disclosures, and signed release configuration.

## External configuration needed

For accounts and cloud backup, create/provide a Firebase project configured for Android package com.rushgames.barrier, enable Email/Password and Google providers, configure the OAuth Android app with production signing certificate fingerprints, and provide generated google-services.json locally at app/google-services.json. Do not commit private server credentials. Firestore additionally needs a documented schema, security rules, and privacy/retention decision before writes are enabled. These values are absent and will not be fabricated.

## Staged implementation order

1. Critical foundation: session start/expiry and boot recovery have been hardened; backup exclusions, persistent protection status, safe converter recovery, and permission-revocation handling are implemented in source. The first-release Room v2 baseline is documented and schema 2 is committed. Remaining Phase 1 gate is a fresh full build/test run plus physical-device verification of service recovery, permission revocation, process death and reboot.
2. Core protection: normalized domain rules, one app-block enforcement owner, session/worker lifecycle and device tests.
3. Accounts/cloud: implement after Firebase/OAuth/backend configuration is supplied; use emulators/test providers.
4. Advanced protection: remove or replace heuristic classifier from enforcement; constrain content fetches.
5. Release: disclosures, signed AAB setup, Play Console and physical-device verification.
